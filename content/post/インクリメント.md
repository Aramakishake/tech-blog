# インクリメントは前置？後置？
## 導入：C++参考書にて
C++の参考書を繙いていたところ、インクリメントが前置されていた(++i)。

個人的には漠然と後置派で、あまり意識せず使用していた。

改めて違いについて調べた結果、以下の通り。

- 前置と後置の違い
  - 例(int i = 3と仮定)
  - int x = i++
    - 処理順序：代入→インクリメント
      - x = 3
      - i = 4
  - int x = ++i
    - 処理順序：インクリメント→代入
      - x = 4
      - i = 4
- この違いにより何が変わるか
  - 前置の場合、インクリメント前の値のコピーが行われうる
  - 後置の場合、インクリメント前の値はコピーされない
  - つまり、インクリメント前の値を使用しない限り冗長処理（インクリメント前の値のコピー）が走る

## 本題1：整数やポインタのインクリメント
調べた結果から、
<u>**この冗長処理の影響が大きくなるのは、インクリメント対象の変数コピー処理が重い場合**</u>
であることが分かった。

このインクリメント対象、for文でよく用いる。
ソースは手癖で書いてるので後置で記述。
```
int number = 10;
int sum    = 0;
for(int i=0; i < NUMBER; i++)
{
    sum += i;
}
```
このケースにおいては、正直前置/後置は気にしなくて良いと考えている。

というのも、`i`は整数型(intの4Byte)であるため、コピー処理は重くないため。

また、あまり推奨されないやり方ではあるが、ポインタ型をインクリメントする使われ方もある。

たとえば、これは`Hello`を1文字ずつコンソールに表示する(クソ意味ない)コード。
```
char str[] = "Hello";
char *p = str;
while(*p != '\0')
{
    std::cout << *p;
    p++;
}
```
これも、ポインタの後置インクリメントは高々8Byteのため、コピー処理は重くならないだろう。

高々といっているのは32bitアプリでは4Byte, 64bitアプリでは8Byteであるため。

なお、ポインタのインクリメントが推奨されないのは、
- 領域外参照
- 領域外編集

ができてしまい、任意コード実行ができちゃうため良くないという理解。

## 本題2：C++では前置の方が良いかも

ただ、C++ではコピーの重い場合が存在する。

filter viewを絡めたiteratorが該当する。

これはどのようなものかというと、
- 配列から特定の条件を満たすものを取得
- 順序

まず、filter viewの例としてはこんな感じ。
```
auto r = v | std::views::filter([](int x){
    return x % 2 == 0;
});
```
配列vからmod 2が0(偶数)となるような要素を取ってくるというもの。

iteratorは、filter viewの`r`のどの位置を指しているかというもの。
```
// itは配列vのうち、偶数となる先頭の要素を指している
auto it = r.begin();

// itはインクリメント可能(次の偶数となる要素を指すようになる)
it++;
```
このiteratorの中には偶数判定メソッドも含まれる。

そのため、コピーをするとなると、通常のイテレータ(vectorとかmapとか)よりもかなり重くなる。

実際のサイズは実装次第であるため、どの程度重くなるかは言及できないが、
確実に冗長なコピーが効いてくることになる。

そのため、C++では前置の方が良いのでは、と考えるに至った。

## 振り返り：なぜ、この点について未学習でなんとかなっていたのだろうか？

2点考えられる。
- おそらく最初に読んだ参考書に起因している
- わかりやすさの観点から処理を複数行に分離する

### (理由1) 最初に読んだ参考書

私が初めて腰を据えて学習した言語はCであり、
Cは前置でも後置でも冗長性をほぼ無視できるためだと思われる。

### (理由2) わかりやすさの観点

労働としてのプログラミングの仕草として、なるべく平易なコードとなるような心がけをしている。
わかりやすさの観点からは、インクリメントと代入は分けたほうが良いと考えている。

## まとめ

- インクリメントは前置/後置で処理の順序が変わる
  - x = ++i(前置)：iをインクリメントしたあと、xにiを代入
  - x = i++(後置)：xにiを代入したあと、iをインクリメント

- 性能的な観点で前置の方が好ましい
  - Cではどっちでも良い
  - C++では重いiteratorのインクリメントがありうるため
